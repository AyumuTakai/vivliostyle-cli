# このフォークにだけある機能と修正

このリポジトリ（[AyumuTakai/vivliostyle-cli](https://github.com/AyumuTakai/vivliostyle-cli)）は、公式の [Vivliostyle CLI](https://github.com/vivliostyle/vivliostyle-cli) の個人用フォークです。公式にない機能と修正をここにまとめます。

公式の変更は定期的に取り込んでいます。取り込むたびに、テストと、実際の本（169 ページ）を並列ビルドと直列ビルドで組んだ結果の比較で確認しています。

組版エンジンにだけある機能（ページ初出のみのルビ `-viv-ruby-repeat` など）は、[vivliostyle.js のフォークのドキュメント](https://github.com/AyumuTakai/vivliostyle.js/blob/master/docs/fork-features.md)にあります。それらの機能は、フォークのビューアで組版したときに使えます（下の `vn` コマンドと `VS_CLI_VIEWER_ROOT` を参照）。

## 機能

### 大きな本の並列ビルド（既定で有効、実験的）

本をいくつかのパートに分けて並列のプロセスで組版し、PDF を結合します。ページ番号、目次、しおり（アウトライン）、リンクは、本全体を一度に組版した場合と同じになります。

- 150 ページ以上の本で働きます。最初のビルドで本全体を組版してページ数などを覚え、次のビルドから分割します。
- 名前付きページで始まる文書の前で分けます。それだけでは偏るときは他の文書の前でも分け、本全体を組んだ結果と比べて同じだと確かめた分け方だけを使い続けます。
- `-j 1` または設定の `parallel: false` で無効にできます。`-j/--jobs` と `parallel: { jobs, splitBefore }` でプロセス数や分け方を指定できます。

詳しくは [parallel-build.md](parallel-build.md)（[日本語](ja/parallel-build.md)）を参照してください。

### コンパイルキャッシュ（`compileCache`、オプトイン、実験的）

変更のない原稿は、HTML への変換を省きます。キーは、原稿の内容、変換の設定、設定ファイルの側のコード（スクリプトやロックファイル）、CLI と Node.js のバージョンです。

- 設定の `compileCache: true`（または `{ exclude, maxSize }`）か、`--compile-cache` で有効にします。
- 変換が外部の状態（時刻、環境変数、ネットワークなど）に依存する原稿は、`exclude` で除いてください。

詳しくは [compile-cache.md](compile-cache.md)（[日本語](ja/compile-cache.md)）を参照してください。

### 原稿側の CSS からエントリーコンテキストの外への `@import` をエラーにする

エントリーコンテキストの中の CSS が、相対パスでエントリーコンテキストの外のファイルを `@import` していると、ビルドをエラーで止めます。外のファイルは出版物に含まれず、組版のときに 404 になるためです。エラーには、該当する CSS と `@import` を一覧で示します。

- テーマに指定した CSS と、そのテーマが参照するファイルは対象外です（テーマと一緒にコピーされます）。
- エントリーコンテキストの中の CSS は、原稿から使われていないものも対象です（出版物にはコピーされるため）。
- `url()` で参照する画像やフォントは確認しません。

### ビューアの指定（`VS_CLI_VIEWER_ROOT`）と `vn` コマンド

環境変数 `VS_CLI_VIEWER_ROOT` に、ビルド済みのビューアのパッケージのディレクトリ（`lib/index.html` があるもの。たとえば vivliostyle.js のフォークの `packages/viewer`）を指定すると、同梱の公式のビューアの代わりにそれで組版します。

- `--viewer` で URL を指定する方法と違い、ビューアは CLI のサーバーから文書と同じオリジンで配信されます。同じオリジンでないと効かない機能（`<iframe>` の中身の印刷の修正など）も働きます。
- 指定したディレクトリがビルドされていなければ、警告を出して同梱のビューアを使います。
- `vn --version` では、`core:` の後にビューアのディレクトリを表示します。
- 並列ビルドの確認に使うハッシュには、ビューアのスクリプトも含めます（ビューアを替えたら、確認をやり直します）。

`bin/vn` は、隣の `../vivliostyle.js/packages/viewer` がビルドされていれば、それを `VS_CLI_VIEWER_ROOT` に指定して `dist/cli.js` を実行します。

## 修正

- **テーマが参照するファイルのコピー**: エントリーコンテキストの外にあるテーマの CSS をワークスペースにコピーするとき、テーマが相対パスで `@import` する CSS や、`url()` で参照する画像・フォントがコピーされず、404 になっていました。テーマと同じ相対位置にコピーするようにしました。
  - ワークスペースの外に置くことになるファイルは、警告を出してコピーしません。
  - 並列ビルドの確認に使うハッシュにも、これらのファイルを含めます（読み込まれる CSS を変えたときに気づけるように）。
- **2ページ目以降の `<object>`・`<embed>` が PDF で空白になる問題**: ブラウザーは、表示していないページの `<object>`・`<embed>` の中身を捨て、印刷のときに読み込み直します。PDF を作る前に印刷用の表示に切り替え、読み込みを待つ（最大 5 秒）ようにしました。文書にこれらの要素がなければ何もしません。

## 内部の変更

- **ビルドの固定コストの削減**: ビューアの組版完了の待ち方を短くしました（状態を 50 ミリ秒ごとに確認し、ネットワークの静止を待たない）。
- **フォークの CLI の使い方**: 公式の `vivliostyle` コマンドと併用するため、`vn` コマンド（`bin/vn`）として使っています（`bin/vn` へのシンボリックリンクを置きます）。
