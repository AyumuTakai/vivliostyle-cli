# コンパイルキャッシュ (実験的機能)

Vivliostyle CLI は、組版の前に、原稿 (Markdown) を HTML にコンパイルします。文書プロセッサ (VFM とそのプラグイン) が動き、`rehype-mermaid` のようなプラグインは、図表の変換に時間がかかることがあります。コンパイルキャッシュは、その HTML を保存して、変更のない原稿では使い回します。

キャッシュは、既定では無効です。構成ファイルの `compileCache`、または `--compile-cache` で有効にします (`--no-compile-cache` で無効にします)。

```js
// vivliostyle.config.js
export default {
  entry: [/* ... */],
  compileCache: true,
};
```

```js
export default {
  // ...
  compileCache: {
    // キャッシュしない原稿: エントリーのコンテキストからの相対パス、ファイル名、ディレクトリ
    exclude: ['colophon.md', 'generated/'],
    // キャッシュの大きさ。超えたら、古いファイルから削除します (既定: 512MB)
    maxSize: '256MB',
  },
};
```

計測に使った 169 ページの本では、キャッシュを使うと、1 つのプロセスでのビルド (24.3秒が 19.5秒)、[並列ビルド](./parallel-build.md) (13.6秒が 10.9秒) のどちらも、約 20% 短くなりました。

## キャッシュした文書が何に依存するか

次のどれかが変わると、その文書はコンパイルし直します。

- 文書の原稿
- コンパイルのオプション: 題名、言語、エントリーのテーマ、VFM のオプション、ワークスペースでのコンパイル後のファイルの場所
- 構成のコード: 構成ファイルのあるディレクトリの、スクリプト (`.js`、`.mjs`、`.cjs`、`.ts`、`.mts`、`.cts`) と JSON ファイル (`node_modules`、名前が `.` で始まるディレクトリ、ワークスペース、出力先のディレクトリを除く)、および、プロジェクトのロックファイル (`pnpm-lock.yaml`、`package-lock.json`、`yarn.lock` など。構成ファイルのディレクトリと、その上 3 階層までで探します)
- Vivliostyle CLI と Node.js のバージョン

構成がファイルにない場合 (API の `configData`) や、構成ファイルの近くに調べるファイルが 5,000 個を超える場合は、警告を出して、キャッシュを使いません。

## 向かない場合

文書プロセッサやプラグインが外から読むものは、キャッシュには分かりません。コンパイル後の HTML が次のものに依存する場合は、使わないか、その原稿を `exclude` で除いてください。

- 時刻 (たとえば、現在の時刻を書き込む `vfm.replace` のハンドラ)
- 環境変数、ネットワーク、構成ファイルのあるディレクトリにないファイル
- プラグインが HTML のほかに書くファイル。コンパイル中に、その文書の HTML 以外のファイルがワークスペースに増えた場合は、その文書はキャッシュしません

## キャッシュの場所

プロジェクトの `node_modules/.cache/vivliostyle-cli/compile/` です。`node_modules` がない場合は、OS のキャッシュディレクトリ (`~/.cache/vivliostyle-cli/<プロジェクトのハッシュ>/compile/`) です。キャッシュを消すには、そのディレクトリを削除してください。
