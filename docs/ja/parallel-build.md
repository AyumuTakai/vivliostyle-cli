# 大きな本の並列ビルド (実験的機能)

数百ページの本は、1 つのブラウザでページを順に組版するため、ビルドに時間がかかります。Vivliostyle CLI は、大きな本をいくつかのパートに分け、パートを並列のプロセスで組版し、できた PDF を 1 つにまとめます。

この機能は実験的です。パートごとに固定のコスト (プロセスやサーバーの起動、コンパイル、ビューアの読み込み) がかかるので、約 150 ページに満たない本では、速くなる効果は小さくなります。

## デフォルトで有効です

設定は要りません。`vivliostyle build` は次のように動作します。

1. 本の最初のビルドは通常のビルドです。このとき、本を調べます。各エントリーのページ数と、各エントリーが名前付きページ (章扉などの CSS の `page` プロパティ) から始まるかどうかです。結果は、プロジェクトの `node_modules/.cache/vivliostyle-cli/` に保存されます (`node_modules` がない場合は、ワークスペースのディレクトリに保存されます)。150 ページに満たない本は調べません。
2. 次のビルドからは、150 ページ以上で、名前付きページから始まるエントリーがある本を、そのエントリーの前で、ページ数がそろうようにパートに分け、並列にビルドします。

本を編集してページ数が変わった場合は、正しいページ番号でパートを組版し直し (「[しくみ](#しくみ)」を参照)、新しいページ数を保存します。

無効にするには、構成ファイルで `parallel: false` を指定するか、`--jobs 1` を使います。

```js
// vivliostyle.config.js
export default {
  entry: [/* ... */],
  parallel: false,
};
```

同時に実行するビルドの数は、`parallel.jobs` か、`vivliostyle build` の `-j` (`--jobs`) オプション (`parallel.jobs` より優先されます) で指定しない場合、CPU コア数の半分 (2〜4) です。

```
vivliostyle build -j 8
```

並列でビルドできない本の場合 (「[条件](#条件)」を参照) は、通常どおりにビルドします。その理由は、`parallel` か `--jobs` を指定したときだけ表示します。

## 分割する位置を自分で選ぶ

パートの先頭にするエントリーを自分で選ぶには、`parallel.splitBefore` に、エントリーの `path` を指定します。このとき、自動の選択は使いません。

```js
// vivliostyle.config.js
export default {
  entry: [
    'chapter-covers/ch01.md',
    'chapter01/01.md',
    'chapter01/02.md',
    'chapter-covers/ch02.md',
    'chapter02/01.md',
    'chapter02/02.md',
  ],
  toc: true,
  cover: 'cover.png',
  output: 'book.pdf',
  parallel: {
    jobs: 4,
    splitBefore: ['chapter-covers/ch02.md'],
  },
};
```

上の例では、`chapter-covers/ch02.md` より前のエントリーと、それ以降のエントリーの 2 つのパートに分けて組版します。表紙と目次は別に組版します。

## 分割する位置

自動の選択では、名前付きページから始まるエントリー (たとえば章扉) の前だけで分けます。自分で選ぶ場合は、前のページにレイアウトが依存しないエントリーを選んでください。パートが文章の途中から始まると、パートの最初のページのレイアウトが、本全体を組版したときと少し変わることがあります。最初に一度、並列と通常の両方でビルドして、PDF を見比べることをおすすめします。

パートのページ数は、なるべくそろえてください。ビルドの時間は、最も大きいパートの時間に近くなります。

## しくみ

- パートは、Vivliostyle CLI の子プロセスがそれぞれビルドします。ブラウザは共有します。文書には、本全体でのページ番号が与えられます。ページ番号や、`counter(page)` を使う柱などは、通常どおりに組版されます。
- 前にあるパートのページ数は、前回のビルドの値を使い、ビルドのあとで確認します。値が変わっていた場合 (たとえば原稿を編集した場合) は、影響を受けるパートだけを組版し直します。そのため、**最初のビルドや、ページ数が変わったあとのビルドは、次回以降のビルドの最大で約 2 倍の時間がかかります**。ページ数は、プロジェクトの `node_modules/.cache/vivliostyle-cli/` に保存されます (`node_modules` がない場合は、ワークスペースのディレクトリに保存されます)。
- 目次は、コンパイルした文書から作り、リンクのページ番号はテキストとして書き込みます。
- PDF を結合し、結合した PDF にしおり、リンク、メタデータを作ります。PDF の後処理のオプション (`preflight`、`cmyk` など) は、結合した PDF に適用します。

## 条件

- 構成ファイルから設定を読み込んでいること。
- 出力が 1 つの PDF で、レンダリングモードが `docker` でないこと。
- エントリーに `rel` がないこと。
- インストールした `vivliostyle` コマンドで実行すること (子プロセスは、パッケージの `dist/cli.js` を実行します)。

## 制限

- 結合した PDF には、PDF のタグ構造 (アクセシビリティのための情報) が残りません。
- ページ番号の参照 (`target-counter(..., page)`) は、目次を除き、同じパートの中だけで動作します。
- テーマのパッケージは、パートごとにインストールされます。
- パートごとにブラウザのコンテキストを持つので、通常のビルドよりメモリを使います。
