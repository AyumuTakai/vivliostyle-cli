# 大きな本の並列ビルド (実験的機能)

数百ページの本は、1 つのブラウザでページを順に組版するため、ビルドに時間がかかります。Vivliostyle CLI は、本をいくつかのパートに分け、パートを並列のプロセスで組版し、できた PDF を 1 つにまとめることができます。

この機能は実験的です。パートごとに固定のコスト (プロセスやサーバーの起動、コンパイル、ビューアの読み込み) がかかるので、約 150 ページに満たない本では、速くなる効果は小さくなります。

## 使い方

構成ファイルで、パートの先頭にするエントリーを `parallel.splitBefore` に、同時に実行するビルドの数を `parallel.jobs` に指定します。

```js
// vivliostyle.config.js
export default {
  entry: [
    'chapter-covers/ch01.md',
    'chapter01/01.md',
    'chapter01/02.md',
    'chapter-covers/ch02.md',
    'chapter02/01.md',
    'chapter02/02.md',
  ],
  toc: true,
  cover: 'cover.png',
  output: 'book.pdf',
  parallel: {
    jobs: 4,
    splitBefore: ['chapter-covers/ch02.md'],
  },
};
```

`splitBefore` には、エントリーの `path` を指定します。上の例では、`chapter-covers/ch02.md` より前のエントリーと、それ以降のエントリーの 2 つのパートに分けて組版します。表紙と目次は別に組版します。

同時に実行する数は、`vivliostyle build` の `-j` (`--jobs`) オプションで変えられます。`parallel.jobs` より優先されます。

```
vivliostyle build -j 8
```

並列でビルドできない本の場合 (「[条件](#条件)」を参照) は、その理由を表示して、通常どおりにビルドします。

## 分割する位置の選び方

前のページにレイアウトが依存しないエントリーを選んでください。たとえば、名前付きページで必ず新しいページから始まる章扉です。パートが文章の途中から始まると、パートの最初のページのレイアウトが、本全体を組版したときと少し変わることがあります。最初に一度、並列と通常の両方でビルドして、PDF を見比べることをおすすめします。

パートのページ数は、なるべくそろえてください。ビルドの時間は、最も大きいパートの時間に近くなります。

## しくみ

- パートは、Vivliostyle CLI の子プロセスがそれぞれビルドします。ブラウザは共有します。文書には、本全体でのページ番号が与えられます。ページ番号や、`counter(page)` を使う柱などは、通常どおりに組版されます。
- 前にあるパートのページ数は、前回のビルドの値を使い、ビルドのあとで確認します。値が変わっていた場合 (たとえば原稿を編集した場合) は、影響を受けるパートだけを組版し直します。そのため、**最初のビルドや、ページ数が変わったあとのビルドは、次回以降のビルドの最大で約 2 倍の時間がかかります**。ページ数は、プロジェクトの `node_modules/.cache/vivliostyle-cli/` に保存されます (`node_modules` がない場合は、ワークスペースのディレクトリに保存されます)。
- 目次は、コンパイルした文書から作り、リンクのページ番号はテキストとして書き込みます。
- PDF を結合し、結合した PDF にしおり、リンク、メタデータを作ります。PDF の後処理のオプション (`preflight`、`cmyk` など) は、結合した PDF に適用します。

## 条件

- 構成ファイルから設定を読み込んでいること。
- 出力が 1 つの PDF で、レンダリングモードが `docker` でないこと。
- エントリーに `rel` がないこと。
- インストールした `vivliostyle` コマンドで実行すること (子プロセスは、パッケージの `dist/cli.js` を実行します)。

## 制限

- 結合した PDF には、PDF のタグ構造 (アクセシビリティのための情報) が残りません。
- ページ番号の参照 (`target-counter(..., page)`) は、目次を除き、同じパートの中だけで動作します。
- テーマのパッケージは、パートごとにインストールされます。
- パートごとにブラウザのコンテキストを持つので、通常のビルドよりメモリを使います。
